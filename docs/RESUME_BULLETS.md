# 简历项目描述（债券版，27届投递用）

## 个人优势第 3 条

3、独立构建 AI Agent 产品能力。基于 Claude Code/Codex 深度实践和实际债券担保尽调场景，独立完成债券担保尽调 Agent 的产品设计、开发与评测（确定性规则 + LLM 增强双引擎、Human-in-the-loop、防幻觉约束），具备 AI 产品从定义到落地的完整能力。

## 个人项目板块（核心技术第 1）

**研担债券担保尽调 Agent｜独立产品设计 + 独立全栈开发**

1. **核心技术**：前端 React + TypeScript + Vite；后端 Python + FastAPI + SQLite；PDF/Word/Excel 解析（PyMuPDF、python-docx、openpyxl）；大模型 API 结构化调用与逐章 Prompt 体系；jieba + BM25 证据检索；pytest + Playwright 自动化测试。
2. **项目描述**：面向债券担保项目经理的 AI 尽调工作台，以募集说明书和信用评级报告为核心输入，打通文本型 PDF/Word/Excel 解析、页码/段落/单元格级证据追溯、人工复核和 17 章专业报告导出。
3. **产品设计**：从债券担保保前尽调的真实痛点（长文档口径核验难、报告初稿耗时）出发，独立定义需求、设计六工作区产品架构（材料/证据/财务核验/复核/风险方案/报告），完成前端交互设计与全栈开发。
4. **AI 边界设计**：采用"确定性规则 + LLM 增强"双引擎——八项三年融资担保核心指标、专项偿债指标与 19 条版本化规则均由代码计算；17 章报告仅六章使用证据白名单内的模型润色，并受数字、主体、口径和引用校验约束。事实冲突并列保留，候选风险经人工确认后才进入正式风险。
5. **表格链路工程化（本轮重点）**：把尽调里最容易出错的三张报表做成"可渲染—可解析—可核对—可交付"的闭环——
   - 用显式三张报表模型替换原先的标量派生（旧实现现金余额与现金流量表相差 5,126 万元），**勾稽不变量在 pydantic 构造期强制**，构造不出来直接报错；自建 PDF 表格渲染器支持多级前导块、分组行、合计行加粗、跨页续表重复表头和单元格稳定标识；
   - 自研表格解析器（`table-extractor-v1`）：只用 PDF 本身信息（不读案例定义、不查数据库），表名靠「单位行上一行」位置锚定而非字面前缀，跨页续表按"只重复表头"与同页另一张表区分，没把握的表标 `needs_review` 而不是让模型补齐；
   - 定义 `TableBlock v1` 契约（三种表型 × 三种来源模式）承载**三条安全不变量**：业务数据格必须可追溯、同主体同期间同口径的多个披露值必须全部保留、**冲突时禁止自动择一**（采用值必须为空并标注待人工确认）。校验结论只有 `passed` / `blocked`，违反即**硬阻断交付**，且判定不含任何模型判断；
   - 报告财务/现金流/债务/评级四章表格由代码生成、进入模型上下文后**逐字保留**、不计入正文篇幅，模型只能写表后分析、不得自出表格；核对接口与前端工作区**只追加不覆盖**，人工更正后原始提取值仍可查；前端、Markdown、Word 三出口读同一份 `TableBlock`，结构上不存在第二套数字。
6. **评测闭环**：6 套虚构债券金标案例确定性回归字段准确率 100%、规则风险召回率 97.62%、关键冲突召回率 100%，零模型成本；表格链路实测 61/61 张表召回、1923/1923 单元格逐格准确（含篡改、换年、跨主体、缺前导块四组负例防止空转）；真实 Agent 评测 18 次字段准确率与风险召回率均 100%；后端回归与桌面/移动端 Playwright 场景覆盖 Prompt 注入、幻觉数字、模型失败降级、主体快照和证据溯源。
7. **真实材料接入**：接入中邮证券公司债真实公开材料（含 252 页募集说明书和评级报告），自动生成统一完整尽调报告，识别 3 年/5 年品种、30 亿注册与 20 亿本期口径、中国邮政集团保证、AA+/AAA 评级，并与虚构案例评测严格隔离，不输出承保、额度或审批结论。

## 面试记牢

- 确定性 100% 与 Agent 18 次 100% 均来自六套虚构债券案例，不代表现实客户效果。
- **表格的 100% 要说清性质**：案例 PDF 由本仓库渲染器生成、金标由案例模型建立，所以它是"渲染—解析"闭环的回归防线（保证改坏一格会被发现），**不是**对第三方真实材料的泛化证明；负例（篡改/换年/跨主体/缺前导块）是它有效的前提。
- **参考材料上的真实表现要如实说**：中邮、北投募集说明书可定位 60%–73% 带表名与单位的表，评级报告只做到"能看见表"（表名 0、单位 0、100% 待确认）——这是已知能力缺口，不是通过项。
- 中邮是真实公开参考材料，系统生成统一"完整尽调"（补充原件缺口明确标注），不将披露信息表述为独立底稿核验。
- LangChain 未使用——核心技术列的是项目真实技术栈（大模型 API 直连 + jieba/BM25 检索），不要口头加 LangChain 或向量 RAG。
- Agent 输出风险、核验要求、缓释建议和债券发行前条件，但不输出承保、额度、费率或最终审批决定。
- 不要说"表格由模型生成/模型核对"——表格是代码生成、代码校验、人工核对；模型在表格链路上的职责只有"表后分析"，且不得改动或复述表内数字。
