# 财务表格结构参考说明

本文件是 `PLAN_material.md` Phase 1 的交付物：把本地公开参考材料中的**表格结构约定**整理成可执行的规格，供虚构案例的 PDF 渲染器（Phase 2）、表格解析器与金标（Phase 3）、以及 `TableBlock v1`（Phase 4）共同遵循。

## 0. 边界与来源

- **本文只记录结构，不复制数据。** 不摘录真实企业名称、数值、文字段落、机构名称、报告编号或版式视觉标识。文中的数值一律以 `x` / 占位形式表示。
- **不自动生成金标。** 参考材料只用于人工结构审阅；金标（`table` / `table_cell` / `table_note` / `table_relation`）一律在虚构案例上建立。
- **参考原件不进入 Git 仓库**（原件位于 `.data/demo_materials/`，该目录已在 `.gitignore` 中）。
- **中邮、北投只作结构参考与版式兼容样本**，未逐格人工标注前不计入单元格准确率。

## 1. 章节位置与表序

财务报表集中在「发行人财务会计信息及主要财务指标」章节，顺序固定：

```text
（一）最近三年财务报表
    ├─ 合并资产负债表        （跨页）
    ├─ 合并利润表            （跨页）
    ├─ 合并现金流量表        （跨 2 页）
    ├─ 母公司资产负债表      （跨页）
    ├─ 母公司利润表          （跨页）
    ├─ 母公司现金流量表      （跨 2 页）
    └─ 非经常性损益明细表
（二）主要财务指标
（三）资产结构 / 货币资金 / 结算备付金 / 融出资金 / 买入返售 / 交易性金融资产等明细
```

虚构案例（华辰）只做**合并口径**，不生成母公司报表；但渲染器与解析器必须能处理「合并 + 母公司并存」，以便中邮、北投的兼容性测试通过。

## 2. 表名前导块（解析器最可靠的锚点）

每张表之前固定是三行结构：

```text
<表名行>          ← 表名，例如「合并资产负债表」「公司货币资金明细」
单位：万元        ← 单位行，可为「单位：万元、%」
项目              ← 表头首格
```

实测要点：

- **表名前缀并不统一**：参考材料中同时出现 `表：`、`表/图` 前缀，以及无前缀的表名。因此**不得以「表」字开头识别表名**；可靠规则是「`单位：…` 行的上一行即表名，下一行即表头首行」。
- **单位行在表外**，不是表格的一行。单位可以是 `万元`，也可以是 `万元、%`（含占比列时）。
- **表头首格不固定为「项目」**：明细表可为「非经常性损益项目」「账龄」「债权单位名称」等。不得硬编码。

## 3. 年度列顺序与口径词

- **年度列按倒序排列**（最新年度在最左），实测为 `2025 年末 | 2024 年末 | 2023 年末`。
- **口径词随报表类型变化**：

| 报表类型 | 列头口径词 |
| --- | --- |
| 资产负债表 | `年末`（时点） |
| 利润表 / 现金流量表 | `年度`（期间） |
| 明细表 | `年末` 或 `年度`，另可附 `占比` 列 |

- 年度值使用阿拉伯数字 + 半角空格 + 口径词（`2025 年末`）。解析器需容忍年份与口径词之间的空格差异。

## 4. 表头层级

- 三张主表为**单层表头**：首格 + 三个年度列。
- 明细表与指标表可出现**两层表头**（分组表头 + 子列），例如「金额 / 占比」「余额 / 坏账准备 / 账面价值」。
- 多级表头在第一行只有部分列有值，其余留空——解析器需按列位置继承上层表头，不得按行拼接文本。

## 5. 科目分组行

- 分组行**只有首格有文字，其余单元格为空**。实测形态：

```text
资产：      （其余三列为空）
负债合计    （属于小计行，见第 6 节）
所有者权益：（其余三列为空）
```

- 典型分组行：`资产：`、`负债：`、`所有者权益：`、`一、经营活动产生的现金流量：`、`二、投资活动产生的现金流量：`、`三、筹资活动产生的现金流量：`。
- 分组行**不参与加总**，只作为层级标签；渲染时首格文本、其余列留白。

## 6. 小计、合计行

- 名称形态：`…小计`、`…合计`、`…总计`、`…净额`、`资产总计`、`负债合计`、`所有者权益合计`。
- **重要实测结论：参考材料中合计行并未使用加粗或其它字体差异**（同一页所有表格文字使用同一字体、同一字号、同一 flags）。因此：
  - **解析器与金标不得依赖字体粗细识别合计行**，必须按名称模式识别；
  - 渲染器**应当**对合计行加粗（`PLAN_material.md` Phase 2 要求），但这是虚构材料的可读性增强，不能反过来成为解析前提。
- 合计行位置：小计行紧跟其明细科目之后；`资产总计` / `负债合计` / `所有者权益合计` 位于对应分组末尾。

## 7. 数值格式

| 形态 | 写法 | 说明 |
| --- | --- | --- |
| 正数 | `1,234,567.89` | 半角千分位，2 位小数 |
| 负数 | `-2,268.79` | 负号前缀；利润表科目名可含「损失以"-"号填列」 |
| 零值 | `-` | 单个半角连字符 |
| 不适用 / 无数据 | `—` | em dash |
| 空白 | 空单元格 | 分组行与非适用列均可能为空 |

解析器需同时容忍 `-` 与 `—` 两种空值写法，并区分「零」与「空」。占比列保留 2 位小数。

## 8. 跨页续表与重复表头

实测确认（合并资产负债表 p96→p97、合并利润表 p97→p98、合并现金流量表 p98→p100）：

- 续表页**只重复表头行**（`项目 | 年度列…`），**不重复表名、不重复单位行**。
- 因此：
  - **解析器**必须把「表头重复 + 无表名 + 无单位行 + 紧接上页表尾」判定为**同一逻辑表的续表**，并记录跨页关系；不得当作新表。
  - **区分续表与「另一张表」的关键**是表名前导块：母公司报表起首页有完整的「表名 + 单位」前导块，续表页没有。
- **渲染器**生成跨页表时必须重复表头，且续表页不重复表名与单位行。

## 9. 合并与母公司并存

- 合并报表与母公司报表**表名相邻、结构相同、同一批年度列**，数值不同。
- 解析器必须依据表名区分口径（`合并` / `母公司`），并把口径写入表格对象与单元格；不得按页序或数值相似度推断。

## 10. 表注

- 表注位于表格**下方**，以 `注：` 开头，可含编号（`注：1、…`）。
- 表注内容分两类：① 指标计算方法说明；② 口径与调整说明。
- 表注必须作为独立对象保留（`table_note`），可被报告引用，且**不得被模型改写或删除**。

## 11. 应收账款明细与账龄结构

参考材料中该类结构以**独立小表**呈现（表名含「账龄结构」），而非主表的一部分：

```text
表：截至 <年度> 年末应收账款账龄结构
单位：万元、%
账龄 | 余额 | 占比
1年以内（含1年） | x | x
1至2年          | x | x
2至3年          | x | x
3年以上          | x | x
合计            | x | x
```

- **账龄档位固定四档**：`1年以内（含1年）`、`1至2年`、`2至3年`、`3年以上`。
- `合计` 行位于末尾，占比列合计为 `100.00`。
- **主要欠款方结构**为另一张表，列形如：`债务人名称 | 是否为关联方 | 期末余额 | <原因/状态列>`，末行为 `合计`。该表可能引用关联方标识，需与事实层的关联方口径一致。

## 11.5 评级报告的表格没有表名前导块（实测）

募集说明书与评级报告在这一点上**结构不同**，解析器必须区别对待：

| 材料 | 表格抽取（实测） | 含表名 | 跨页续表 |
| --- | --- | --- | --- |
| 中邮募集说明书 | 78 张 | 47 张 | 20 张 |
| 北投募集说明书 | 81 张 | 59 张 | 27 张 |
| 中邮信用评级报告 | 37 张 | **0 张** | 0 张 |
| 北投信用评级报告 | 132 张 | **0 张** | 0 张 |

两份评级报告里的表格**直接跟在页眉或节标题之后**，上方既没有表名行也没有 `单位：` 行
（实测：中邮 p4 表格上边界 145，上方只有页眉两行；p6 表格上边界 78.9，上方只有节标题）。
因此按第 2 节的前导块规则无法恢复表名——这是**材料的真实结构**，不是解析缺陷。

处置方式：

- 解析器对这类表把 ``caption`` 与 ``unit`` 留空、置信度降为 0.45 并标记 ``needs_review``，
  **不猜测、不用邻近标题冒充表名**；
- 它们不计入单元格准确率（Gold 分层规则），只验证「表格能否被定位到」；
- 若后续需要，可在核对工作区人工补录表名，补录结果创建新版本、不覆盖原始抽取值。

## 12. 其它主要科目明细表

- 表名形态：`公司<科目>明细`；单位可为 `万元` 或 `万元、%`（含占比列）。
- 常见列：`项目 | 金额 | 占比`、`项目 | 期末余额 | 期初余额`、`债权单位名称 | 是否为关联方 | 期末余额 | <状态>`。
- 有息负债类明细需能还原出小计（短期借款 / 一年内到期的非流动负债 / 长期借款 / 应付债券），并与主表小计勾稽。

## 13. 对渲染器（Phase 2）的硬要求

1. 第一列宽、年度列窄；列宽不随行数变化。
2. 表外三行前导块：**表名 / 单位 / 表头**，顺序与内容同第 2 节。
3. 分组行：首格文本、其余列留白。
4. 合计行加粗。
5. 负数、零值（`-`）、不适用（`—`）、空白四种形态都可表达。
6. 表宽超出页宽时按页宽等分；**表高超出页面时自动分页并重复表头**（当前 `_draw_table()` 无分页能力，表高超出会被静默裁剪，必须重写）。
7. 表注排在表格下方，与表格同页或在紧邻页。
8. 每个单元格有稳定标识与坐标，供金标与核对接口引用。
9. 页脚保留模板版本与「虚构案例」标识。

## 14. 对解析器与金标（Phase 3）的硬要求

1. 表格对象须含：`table_key`、表名、页码与跨页关系、行列、单元格原文与坐标、表头层级、单位/币种/口径、表注、提取方法与置信状态。
2. 跨页续表的合并规则见第 8 节；无法稳定恢复的表格标记待人工确认，**不让模型补齐**。
3. 金标类型：`table`、`table_cell`、`table_note`、`table_relation`；单元格金标需含原始值、规范化值、单位、口径、与事实字段的映射。
4. 合计行、分组行的标注**按名称模式**，不按字体。
5. 覆盖以下负例场景：年度倒序、合并与母公司并存、跨页续表、负数/零值/`—`、单元格篡改、换年、跨主体引用。

## 15. 与现有实现的差距（本轮待补）

| 项 | 现状 | 目标 |
