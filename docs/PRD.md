# PRD：研担债券发行融资担保尽调 Agent

## 用户与问题

核心用户是融资担保项目经理和风险审查人员。系统针对企业债券发行担保场景，以募集说明书和信用评级报告为核心交易材料，并与审计、债务、法律、保证合同和反担保材料交叉核验。

## 产品边界

1、当前产品只处理企业债券发行融资担保的保前尽调，不提供贷款担保项目入口，也不允许新建贷款担保项目。
2、历史数据库中的贷款项目、表结构、接口兼容字段和旧评测文件只用于迁移、只读查看与回归兼容：不进入当前导航，不参与债券 Agent、Pilot、baseline 或指标汇总，也不作为当前产品能力或效果对外宣称。
3、兼容不等于继续建设贷款能力。本轮不承诺删除旧贷款表、旧字段或历史代码，也不通过破坏性迁移清理用户已有数据；后续如需下线历史兼容，应另行制定备份、迁移、验证和回滚方案。

## 产品目标

- 完成“创建债券项目 → 上传募集说明书/评级报告及底稿 → 断言与冲突 → 债券偿债指标与规则 → 人工复核 → 风险条件 → AI润色生成尽调报告 → 导出word尽调报告”闭环。
- 所有材料事实、核验和风险均可回到 PDF 页码、Word 段落或 Excel 单元格。
- 报告里的财务、现金流、债务、评级四章由系统生成规范化表格，表格与正文分职：表格负责数值，正文负责分析；同一张表在前端、Markdown 和 Word 三出口完全一致。
- Agent 提供报告生成，提供风险、核验动作、缓释建议和担保前条件；确定性评分只用于风险状态排序，不输出建议担保、暂缓、通过、拒绝、额度或费率结论。

## 用户流程

1. 用户从主体档案库选择发行人，配置本次交易的保证人、反担保方及反担保安排，再填写债券名称、发行规模、期限和募集资金用途。
2. 系统冻结发行人档案版本及项目交易主体信息，形成项目主体快照；档案后续更新不会自动改变历史项目。
3. 用户上传核心材料债券募集说明书和主体信用评级报告；审计、债务、法律、保证合同和反担保材料可作为补充核验资料上传。
4. 系统解析并分类文本型 PDF、DOCX、XLSX，展示解析质量、完整尽调就绪度、核心材料缺口及补充核验材料。
5. 主体快照证据与项目材料共同形成事实断言；相同主体、字段、期间和口径的不同值并列保留，人工选择后形成已确认规范事实。
6. 确定性代码按三个完整年度计算八项融资担保核心财务指标，并补充利息保障、DSCR、到期集中度和担保覆盖等专项指标；债券 `bond-v1` 政策包执行 19 项规则并保存公式、输入、阈值、版本和结果。
7. 系统解析材料里的表格，并与主体档案核对后形成系统数据表；用户在「表格核对」工作区逐格核对，可确认或更正。更正只追加不覆盖，原始提取值始终保留。
8. 模型检索支持证据和反证，提出定性候选风险；只有人工确认项进入正式风险矩阵。
9. 材料缺口、冲突、规则材料不足和候选风险生成尽调任务，处理动作写入审计日志。
10. 报告由确定性事实模板组装，财务、现金流、债务、评级四章的表格由代码生成并逐字保留，模型只能在允许证据内写表后分析；用户复核后导出。

## 专业工作区

债券项目驾驶舱、募集说明书与评级报告、财务与偿债核验、担保及反担保、复核中心、专业尽调报告。复核中心下设「表格核对」子视图：左侧表格清单，右侧逐格核对矩阵，单元格显示原始值与规范化值、状态（冲突、缺失、待确认、已采用）、来源定位与最新核对结论，移动端横向滚动。募集说明书、评级报告和主体档案可用时生成统一的“完整尽调”；缺少原件时列为补充核验材料和开放任务，不降低报告等级。风险页使用 3×3 可能性/影响矩阵，并输出核验要求、反担保建议和发行前条件；报告只给出风险状态和未决事项，最终审批决定不在系统范围内。

## 债券项目主体档案与交易角色

主体档案是跨债券项目复用、带版本和证据定位的发行人基础事实库。新建债券项目必须选择发行人档案；保证人和反担保方继续按本次交易在项目中配置，可以引用项目级主体资料和证据，也可以标记“暂未确定”或“反担保不适用”。系统不得把“暂未确定”解释为不存在。旧项目已有的保证人、反担保方多角色档案绑定继续按角色只读兼容，但不因此把多角色档案设为新建项目的强制条件。

发行人档案包含法律身份、股权与实际控制人、三个完整年度财务、债务与到期结构、经营、客户供应商、关联交易和法律合规八个模块。作品固定展示最近三个完整会计年度，不在主体资料和财务章节混入季度、半年度或“最新一期”数据。法律身份、控制关系、三个年度的核心财务、当前债务到期表和重大法律筛查构成 Agent 启动的标准核心包；关键项 `stale | conflicted | insufficient` 时可以建项目，但不能启动 Agent。单一来源且有可靠证据的事实可以用于分析，同时仅作为数据质量提示，不计入人工待办总数。

三年财务按资产负债表、利润表和现金流量表分组展示。主要科目包括货币及受限资金、应收及其他应收、存货、流动和总资产、短期及长期债务、一年内到期债务、应付债券、有息负债、流动和总负债、所有者权益、营业收入及成本、财务费用、利息支出、净利润、销售收现和三类现金流净额。系统只基于同年度、同口径、状态可用的事实计算资产负债率、流动比率、可用现金、现金短债覆盖、有息债务资本化率、应收收入比、现金利润比和经营现金流债务比；缺项或分母为零时显示“无法计算”，不补零也不估算。

报告共保留 17 章。Prompt Contract v3 只对财务、现金流、债务、评级、保证和反担保六个高价值章节调用模型；债券概览、法律及其他十一章由确定性模板生成。模型只负责在章节事实、指标、规则和证据白名单内组织表达，不负责选择冲突值、计算指标、确认候选风险或形成审批结论。

项目快照固定记录发行人档案版本，以及本次交易中发行人、保证人和反担保方的角色关系。档案更新只创建新版本，不覆盖历史版本，也不自动改变已经冻结的项目快照。用户主动刷新发行人快照后，项目分析和既有报告变为过期，必须重新运行 Agent 才能继续导出。

档案证据与项目上传材料分开存储，不计入用户上传的文件数、页数、字符数和材料清单；分析阶段通过统一证据视图完成检索、冲突识别、引用和报告校验。所有断言必须保存 `subject_id`、`subject_role`、期间和口径，确保发行人、保证人、反担保方及其关联主体不会串用。发行人档案值不得自动覆盖募集说明书或评级报告值，评级机构对增信的意见也不得直接转写为担保机构判断。

## 核心验收

- 缺字段不能作为 0 计算，冲突来源不能由 Agent 擅自选择。
- 模型只能返回注册字段和输入中存在的 `source_id`。
- 新增数字或非法引用导致章节回退到确定性模板。
- 自定义项目未配置模型时停在 `model_required`，不生成推测性风险。
- 非演示项目所有读取、修改、引用和导出均验证项目令牌。
- 未确认候选风险进入正式风险清单数量必须为 0；导出存在未决重大事项时必须显示红色警示。
- 系统表格必须同时满足三条不变量，否则判为 `blocked` 且不得进入最终交付：业务数据单元格可追溯（或标注为人工录入并给出依据）；同主体、同期间、同口径的多个披露值全部保留；数值冲突时采用值为空并标注待人工确认，禁止自动择一。
- 同一张表在前端、Markdown 和 Word 三出口的数值、年度、单位与表注必须一致；模型不得改动、重排、复述表内数值，也不得自行输出表格。
- 单元格核对只追加不覆盖：人工更正后，原始提取值仍然可查。
- 贷款担保项目不能从前端或公开创建接口新建，且不得进入债券评测清单、Pilot gate、baseline 和汇总指标。
- 发行人、保证人和反担保方的事实、证据、指标与引用必须按主体角色隔离；主体快照证据不得占用项目上传配额。

## 非目标

不连接真实工商、司法或征信系统，不包含联网新闻、多人协作、保后监控、贷款担保新建流程和自动审批；扫描件 OCR 仅提供可插拔兼容多模态适配器，默认关闭，不使用实习单位客户数据、内部知识库、模板或 Prompt。

## 核心案例边界

六套默认案例统一模拟北交所面向专业投资者公开发行公司债券，旗舰为完全虚构的“华辰精密制造有限公司 2026 年面向专业投资者公开发行公司债券（第一期）”。默认输入只有《募集说明书（申报稿）》和《信用评级报告（拟发行版）》；系统固定生成“完整尽调”，审计、流水、法律、保证合同和反担保权证缺失时列为补充核验材料。华辰旧辅助底稿保留为 `extended_pack`，不进入默认评测。募集说明书与评级报告只表达发行人或评级机构披露，不被直接当作担保机构结论；Agent 不输出是否承保、担保额度、担保费率或审批意见。
